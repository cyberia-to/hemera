## Status and delivered evidence

The exact RF8/RP16 mixed x⁷/total-inverse profile is experimental. Neither its
required cryptographic security nor a full-round collision/preimage break has
been established. Production finalization remains the separate task recorded
in [the persistent plan](../.claude/plans/production-finalization.md).

- Format-independent structural commitments and a `.cyb` adapter separate
  container interpretation from permutation/sponge operations.
- Eidos checks 21 explicit source theorems and rejects 13 negative controls.
  Binary reduction certificates also check reconstruction/range for two actual
  Rust multiplication outputs. Algebraic law parameters remain explicit.
- The full seven-byte hash model has 1161 variables and 1177 equations. Model
  witnesses, single-wire perturbations and four Rust digest vectors are checked.
- The manually translated `reduce128` integer model is checked with Z3; it is
  not extracted Rust, an Eidos universal refinement proof or a security proof.
- Preserved rational and bounded-solver campaigns record reduced problems and
  resource exhaustion honestly. Their limits do not establish attack lower bounds.

`solved_one_coordinate` status is intentional. The former uses linear-factor
extraction; the latter records an older all-factor implementation whose exact

Numerical candidate revalidation establishes consistency, not exhaustive root

The preserved source manifest is
[`research/archive/model-sources-2026-09-11.json`](../research/archive/model-sources-2026-09-11.json),

16-constant iteration and equivalent field assignment operations. Numerical

## Source hygiene and compatibility

Standard formatting covers the workspace; behavioral edits are limited to CPU
code. Iterator/assignment simplifications preserve field operations. Private
recursive helpers group existing bounds without public API changes. Ceiling
division now uses `div_ceil`, avoiding intermediate addition overflow; valid
input results are unchanged. The asynchronous decoder's custom Debug prints
lifecycle flags and omits its reader, payload, root and hash stack. The redundant
test import and constant-assertion warnings are corrected.

This is no cryptographic redesign. Core vectors and known-answer tests pass.
Pre-publication review caught an intermediate hygiene regression in
`889ca46d75ffde90d915cf00dda436eb17fcdb06`: iterating the whole caller-supplied
constant tail changed the number of partial rounds for nonstandard slice lengths.
The final snapshot restores exactly the first 16 internal constants, ignores
excess entries and rejects a short tail as the original implementation did.
Two new regressions fail on that intermediate commit and pass after the fix:
144 versus 145/161 constants must give identical outputs, and every internal
tail length from 0 to 15 must be rejected. Source fingerprints and the complete
CPU/model/Eidos checks were refreshed after the correction.
GPU/CLI source formatting was applied, but this validation does not establish
their execution or the workspace-wide GPU dependency MSRV. The old 500-line
source-file guideline is still exceeded in several existing modules; a module
reorganization was outside this bounded release cleanup.

## Reproducing dependencies

The repository intentionally ignores root `Cargo.lock`. The snapshot preserves
the tested resolution as [`audit/locks/2026-09-12.lock`](locks/2026-09-12.lock),
SHA-256 `f63d26bcf071277a8a4ec6143fc6ff3c533734ac02caae9a2664fcdbb0ba4538`.
From a fresh clone, copy it to `Cargo.lock`; fetch those versions if the cache
is empty, then use the locked commands above. Python checks need Z3 4.15.4;
rational smoke checks need python-flint 0.9.0. Hemera's Eidos checker needs the
matching Eidos source checkout at sibling `../eidos`.

The release archive and provenance file pin the final commits and file hashes.
This preserves reproducible research inputs without claiming a production
security conclusion or republishing a stable library version.
