# audit — cyber-hemera 0.3.1

checked against the crate on disk (`v0.3.1`, `rs` 0.3.1), specs, docs, zheng's copied 736, and `cargo test --workspace` (298 CPU tests passed). GPU tests exist (`wgsl/tests/gpu.rs`) and were not re-run here.

this is not a third-party cryptographic review. it is an internal audit: spec ↔ code ↔ claims. no production sign-off.

## verdict

the permutation, sponge, vectors, and self-bootstrap are internally consistent at R_F=8, R_P=16, x⁷ / x⁻¹, 32-byte output. CPU tests pass. the crate is published as live while the README still says the hash is unaudited and may change.

the security argument that justified cutting partial rounds from 64 to 16 is wrong. collision resistance of the 32-byte particle is 2^128, not 2^256. docs still contain the pre-0.3.0 round count. 736 constraints are a spreadsheet, not a circuit in this repo.

## critical

### 1. algebraic-degree argument for R_P=16 is invalid

`specs/README.md`, `docs/explanation/parameters.md`, `roadmap/inversion-sbox.md` all write:

```
deg = 7^8 × (p−2)^16 ≈ 2^1046
margin = 2^918 over 128-bit
```

over F_p every function interpolates at degree ≤ p−1. x⁻¹ (with 0↦0) already has degree p−2 ≈ 2^64. further inversions do not stack to 2^1024. one inverse S-box saturates the interpolation metric.

Poseidon2 as published uses x^d in every round. Hemera's partial-round x⁻¹ is a novel variant (closer to Rescue/Griffin than to Poseidon2). the 64→16 round cut was sold as a consequence of the stacked-degree formula. that formula does not apply. there is no Gröbner / differential / GCD analysis in this repo for Goldilocks t=16 with inverse partial S-boxes.

until that analysis exists, "2^918 bits of margin" is not a number. R_P=16 is an unproven parameter.

### 2. collision resistance of the particle is 2^128, not 2^256

sponge collision security is min(2^{c/2}, 2^{n/2}):

| bound | bits | source |
|---|---|---|
| inner (capacity c = 64 bytes) | 256 | 2^{512/2} |
| output (n = 32 bytes) | 128 | birthday on the particle |

the particle *is* the 32-byte output. two contents with the same Hemera digest is a 2^128 attack. `docs/explanation/parameters.md` claims 2^256 classical collision for cap=8 and says 32-byte output "preserves 256-bit collision resistance." capacity preserves inner collisions. truncation sets the observable bound.

quantum BHT on a 256-bit digest is ~2^{85}, not the 170-bit figure taken from capacity.

preimage of a 32-byte digest remains 2^256. that claim can stay.

## high

### 3. `docs/explanation/security.md` is a previous hash

table still lists Hemera as R_P=64. that was the pre-inversion parameter set. code, `params.rs`, `specs/README.md` are R_P=16. anyone comparing Hemera to Plonky3/SP1 from this page is reading a dead instantiation.

### 4. published as live, specified as unstable

README line 1: "Unaudited cryptography. Not finalized — hash outputs may change."
`soft3/status.md`: hemera is live, crates.io 0.3.1.
`soft3/conformance`: harness waits for stable hemera output.

a permanent graph cannot sit on a hash that the authors reserve the right to break. pick one: freeze the vectors and drop the warning, or stop calling it live.

### 5. 736 is not measured here

constraint budget is 8×16×4 (full x⁷) + 16×2 (inv) + a guessed MDS term ≈ 736. no circuit in `hemera/` counts this. zheng copies the number into verifier, identity proofs, Merkle costs. if MDS-in-CCS wiring differs, the whole stack's proving-cost tables move.

## medium

### 6. version skew

| artifact | version |
|---|---|
| `rs/Cargo.toml` / git tag | 0.3.1 |
| `CHANGELOG.md` | last entry 0.3.0 |
| `wgsl/Cargo.toml`, `cli/Cargo.toml` | 0.3.0 depending on hemera 0.3.0 |

0.3.1 is the inv addition-chain (`82857d8`). changelog and sibling crates did not move.

### 7. two encodings of a 32-byte value

output: 4 canonical u64 limbs, 8 bytes each.
`keyed_hash`: the same 32 bytes go through the 7-byte absorb path.
`derive_key_material`: the same 32 bytes are loaded as 4 rate limbs and permuted with no padding.

domain tags separate the modes. the bytes are not the same field elements. easy to misuse a Hash as a key.

### 8. domain tag vs "one pure hash"

`specs/capacity.md`: state[11] domain_tag "PLANNED FOR REMOVAL" (`roadmap/one-pure-hash.md`).
`sponge.rs` still writes DOMAIN_HASH / KEYED / DERIVE_* into state[11].
tree flags (state[9]) and length (state[10]) are the real domain separation for particles. the leftover API tags are a second, half-retired mechanism.

### 9. file size vs quality bar

`midao/quality.md`: 500 lines. `tree.rs` 1447, `wgsl/src/lib.rs` 930, `sponge.rs` 820, `sparse.rs` 521, `stream.rs` 510.

### 10. broken / stale docs

- `docs/explanation/README.md` links `[[content-ids]]` (file is `particle-ids.md`) and still says "raw 64-byte CIDs"
- `params.rs` points WGSL at `gpu/poseidon2.wgsl`; shaders live in `wgsl/src/shaders/`

## low

- field arithmetic is a local Goldilocks, not p3_field. add/mul have data-dependent overflow branches. `inv` special-cases zero. the crate is not constant-time. fine for particle identity; not fine if `keyed_hash` is treated as a MAC against timing.
- `Hash::from_bytes` does not check limbs < p.
- `absorbed: u64` written into a field element; wraps if a single sponge exceeds p bytes (~18 EB). irrelevant in practice.
- GPU/CPU cross-check is written; not executed in this audit pass.

## what holds

- params in `params.rs`, permutation structure, and `specs/permutation.md` agree: initial M_E, 4 full x⁷, 16 partial inv, 4 full x⁷.
- `0^{-1}=0`, inv addition-chain tested against Fermat (`inv_chain_matches_fermat`).
- sponge padding 0x01‖0x00*, 7-byte absorb, 8-byte squeeze, length in capacity[2].
- round constants match Hemera₀ bootstrap from seed `63 79 62 65 72` (test in `bootstrap.rs`).
- pinned vectors in `vectors/hemera.json` / `rs/tests/vectors.rs` (empty, hello, hemera, tree, derive_key).
- tree flags prevent leaf/node/root confusion (capacity state[9]).
- 298 CPU tests green.

## fix plan (not applied)

1. rewrite the security section: drop 2^1046 / 2^918; state interpolation degree saturates at p−1 after one inverse; commission or cite an analysis for inverse-S-box Poseidon2 on Goldilocks t=16; until then the round count is a choice, not a theorem.
2. collision table: classical 2^128 (output birthday), preimage 2^256, quantum collision ~2^85. keep capacity 2^256 only as the inner bound.
3. replace the R_P=64 row in `docs/explanation/security.md`.
4. decide freeze vs live. if freeze: changelog 0.3.1, bump wgsl/cli, delete "outputs may change." if not freeze: status.md must not say live.
5. derive 736 from a real constraint list, or mark it estimated everywhere (hemera + zheng).
6. changelog + crate versions; fix the two doc links; one encoding for "32 bytes that are a Hash."

no code changes until this list is accepted.
